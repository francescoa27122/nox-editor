# LSP Hover Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Resting the pointer on a symbol shows its type and documentation.

**Architecture:** Reuses the request door completion opened. A pure module reduces the three shapes of LSP `contents` to ordered code/prose blocks; the editor layer renders them with `textContent` and never `innerHTML`.

**Tech Stack:** TypeScript, CodeMirror 6 (`@codemirror/view`'s `hoverTooltip`), Vitest.

**Spec:** `docs/superpowers/specs/2026-08-18-lsp-hover-design.md`

## Global Constraints

- **Line endings are CRLF.** Verify every edit landed.
- **Another session shares this checkout.** Use `git add <named files>`, never `git add -A`, and confirm `git branch --show-current` before each commit.
- **`npm run check` exits 0 while reporting errors.** Grep its output for `0 ERRORS`; do not trust the exit code in a `&&` chain.
- **Baseline to beat:** `npm test` 1038 / 54 files, `npm run check` 416 files 0 errors.
- **Never `innerHTML`.** Spec §4 — a language server is a third-party process and its text reaches the DOM only through `textContent`.
- **Do not push, open a PR, or merge without asking.**

### Task 2: The hover source and its DOM

**Files:**
- Create: `src/editor/hover.ts`
- Test: `tests/lsp-hover-source.test.ts` (jsdom)

**Interfaces:**
- Consumes: `hoverBlocks` (Task 1), `positionAt`, and the `CompletionDeps` shape already exported from `src/editor/completion.ts` — reuse it rather than declaring a second one.
- Produces: `createLspHoverSource(deps): (view, pos) => Promise<Tooltip | null>` and `lspHoverExtension(deps): Extension`.

- [ ] **Step 1: Write the failing tests**

Cover every row of spec §7 — no server, no `hoverProvider`, no document, a rejecting request, empty contents — each returning `null` and, where relevant, making no request. Then: the response `range` becomes the tooltip's `pos`/`end`; its absence anchors at the hovered position.

Rendering, in jsdom: a code block produces a `<pre>`, prose produces a `<p>`, and — the guard on §4 — server text containing `<img src=x onerror=alert(1)>` appears as literal characters with no `img` element created anywhere in the tooltip.

- [ ] **Step 2: Run and watch fail.**

- [ ] **Step 3: Implement.** `hoverTooltip` source returning `{ pos, end, create }`; `create` builds a `div`, appends a `pre` per code block and a `p` per prose block, each set through `textContent`.

- [ ] **Step 4: Run and watch pass.**

- [ ] **Step 5: Verify the injection guard discriminates.** Temporarily swap one `textContent` for `innerHTML` and confirm the test fails; restore.

- [ ] **Step 6: Commit**

```bash
npm run check 2>&1 | grep -E "ERROR|COMPLETED"
npm test
git branch --show-current
git add src/editor/hover.ts tests/lsp-hover-source.test.ts
git commit -m "Show hover as text, never as markup"
```
